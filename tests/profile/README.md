# Public profile header verification

The focused C++ suite runs without MongoDB or uWebSockets. It requires a C++20
compiler, CMake, nlohmann/json, and GoogleTest. It tests the production slug,
public serialization, privacy, Inja rendering, and SEO helpers.

```sh
cmake -S tests/profile -B build/profile
cmake --build build/profile -j2
PROFILE_PREVIEW_DIR=/tmp/profile-preview ctest --test-dir build/profile --output-on-failure
```

For browser verification, install Playwright and its Chromium browser in your
test environment, then run:

```sh
PROFILE_PREVIEW_DIR=/tmp/profile-preview node tests/profile/browser-check.cjs
```

The browser script starts its own temporary HTTP server and checks five rendered
fixtures at 360px, 768px, and 1280px. Screenshots go to `build/profile/screenshots`.
It checks overflow, font loading, image failures, keyboard focus, and script errors.
Fixture images are illustrative placeholders, not real profile photos.

For full HTTP integration, build and start a test server with its MongoDB and
other normal runtime dependencies. Install Python `pymongo`, then set
`PROFILE_TEST_BASE_URL`, `PROFILE_TEST_MONGODB_URI`, and `PROFILE_TEST_DATABASE`
to that test server and its profile database before running:

```sh
python3 tests/integration/test_public_profile_header.py
```

This script uses unique Persian underscore slugs, creates only test documents,
and removes only the fixture IDs in a `finally` block. It covers both route aliases,
cache hits/misses, privacy updates, redirects, malformed URLs, private/missing
profiles, and business HTML. Contact-field privacy is covered in C++ because
MongoDB contact values require the application's encryption format. Normal
view analytics may be generated by these HTTP requests in the test environment.

## Personal profile editor

The editor suite additionally requires OpenSSL development headers/libraries.
It covers cryptographic keys, legacy token compatibility, Unicode validation,
private drafts, field whitelisting, clearing values, and credential filtering.

```sh
node --test tests/profile/test_autosave.mjs
python3 tests/integration/test_profile_editor.py
PROFILE_TEST_BASE_URL=http://localhost:3009 node tests/profile/editor-browser-check.cjs
```

Both integration scripts require the explicit test variables described above.
The editor HTTP suite exercises cookie origin checks, ownership rejection,
publication, version conflicts, uploads, duplicate slug claims, and the 120/minute
owner limit. Set `PROFILE_API_RATE_LIMIT_REQUESTS=10000` **on the isolated test
server only**, so the separate general limit does not interfere with this test.
The owner autosave limit remains 120/minute.

The browser suite uses the real API and creates a uniquely named temporary
profile. It checks autosave/reload, offline recovery, field deletion, independent
tabs and conflict resolution, publication, and key login/logout. It soft-deletes
its own fixture afterward. Screenshots are written to
`build/profile/editor-screenshots/`; test fixtures and uploads belong in an
isolated database and runtime directory, never the developer's real profile DB.

Example test-server environment (use a dedicated MongoDB instance):

```sh
PORT=3009 \
MONGODB_URI=mongodb://127.0.0.1:27029 \
BASE_URL=http://localhost:3009 \
COMPLIANCE_ENCRYPTION_KEY=0123456789abcdef0123456789abcdef \
PROFILE_API_RATE_LIMIT_REQUESTS=10000 \
/path/to/build/server
```

The encryption key above is a test fixture only. Run the test server from an
isolated directory containing copies of `templates/`, `public/`, and `locales/` so uploaded
fixture images and logs also stay separate. The default profile database name
is `search-engine`; isolate the MongoDB instance as well as the HTTP port.

## Canonical dot slugs

Run against the same isolated test environment:

```sh
python3 tests/integration/test_canonical_profile_slugs.py
```

This suite verifies Persian and English dot slugs, once-decoded URLs, all forbidden
dot combinations, Unicode length limits, person/business redirects in both public
route aliases, legacy profile fallback, normalized creation collisions, and static
asset routing. The older public-header suite deliberately retains legacy underscore
fixtures to verify backward compatibility. No migration renames existing profiles.

Profile storage and performance suites use a unique test database per process,
so repeated CTest runs do not collide with reserved soft-deleted fixture slugs.
